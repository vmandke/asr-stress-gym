# Real-time factor, per adapter

Generated by `scripts/measure_rtf.py` — regenerate rather than edit.
RTF is inference wall-seconds per audio-second: **lower is faster**, and
below 1.0 means the backend keeps up with a realtime stream.

- Measured 2026-09-20 on `Darwin arm64`, single-threaded (`num_threads=1`, matching the
  pinned 1.5 vCPU per worker in `docker-compose.yml`).
- 10 corpus clips, 28.5s of audio, 3 repeats; streaming adapters fed in 200ms chunks.
- Numbers from a developer host are indicative; the reproducible ones come
  from inside the pinned containers.
- These cover a **whole utterance**: every chunk's `infer` plus the
  `finalize` that ends it. A worker's `/health` `rtf_p50` is a *different,
  narrower* number — per-push `infer` only — so it reads lower, and the two
  are not comparable. Finalize is where the streaming adapters push 0.6s of
  tail padding and the non-streaming ones do all of their work at once,
  which is exactly the cost a per-push figure leaves out.

| Adapter | Family | Runtime | Streaming | Serializable | RTF p50 | RTF p95 |
|---|---|---|---|---|---|---|
| `conformer_ctc` | ctc | sherpa-onnx | yes | no | 0.041 | 0.055 |
| `mock` | mock | mock | yes | **yes** | 0.037 | 0.038 |
| `whisper_ct2` | encdec | ctranslate2 | **no** | no | 0.151 | 0.262 |

## Reading this table

`mock` is not a model: it sleeps on a fixed RTF constant (`adapters/mock.py`) so the gateway's own behaviour can be measured without a model's variance underneath it. Its row is a control, not a result.

`serializable` is the column that decides which recovery path a failover takes. Only `mock` is serializable, so only `mock` exercises the warm-checkpoint tier; every real adapter degrades to audio replay, which is the documented and expected outcome rather than a gap — sherpa-onnx and CTranslate2 expose no way to serialize inference state (docs/implementation-plan.md, "Findings that change the design").

`streaming: no` on the two Whisper adapters is why the router filters on capabilities before it scores: they are healthy backends that must never receive a mid-utterance chunk.
